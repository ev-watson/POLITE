## Next session: verification procedure (run in order)

**Prerequisite:** Close EZCAP and all QHY processes. ASCOM Remote Server can stay up for EFW/Pyxis only.

### Step 1 — SDK scan (2 min)

```powershell
cd C:\path\to\POLITE\third_party\alpaca-qhyccd-camera
..\..\..venv\Scripts\python.exe scripts\scan_qhy_cameras.py
```

- **Pass:** prints `QHY268M-<serial>` or similar  
- **Fail:** set `$env:QHYCCD_DLL` to the DLL path EZCAP uses; replug USB; retry

### Step 2 — Start camera Alpaca server (leave running)

```powershell
.\scripts\start_qhy_alpaca_server.ps1
```

Verify: `curl http://localhost:11112/management/apiversions`

### Step 3 — Camera-only smoke test

```powershell
cd C:\path\to\POLITE
.\.venv\Scripts\python.exe scripts\qhy_alpaca_smoke_test.py --exposure 2 --out D:\tmp\qhy_smoke.fits
```

- **Pass:** FITS written; open in FITS viewer; check ~6248×4176, ADU pedestal sane  
- **Fail:** capture server window traceback + client error ? patch driver (likely `usb_traffic`, connect timing, or readout mode)

### Step 4 — Full chain (only if Step 3 passes)

```powershell
.\.venv\Scripts\python.exe scripts\observatory_smoke_test.py
```

Requires PWI4 + ASCOM Remote Server (EFW + Pyxis on `:11111`).

### Step 5 — Decision tree

| Result | Action |
|--------|--------|
| Step 1 fails | DLL/path/USB conflict — do not patch Alpaca code yet |
| Step 1 OK, Step 3 fails on connect | Read server log; try serial in `config.windows.yaml`; ensure EZCAP closed |
